## mok

mok is a live coding environment for the browser — a personal fork/reimagining of [flok](https://flok.cc) by Damián Silvani. It supports three targets:

| Target | Runs where | Needs setup |
|---|---|---|
| **Strudel** | In-browser | None — works immediately |
| **Hydra** | In-browser | None — works immediately |
| **TidalCycles** | Local interpreter | SuperCollider + flok-eval relay |

### Key references
- **Flok** (the inspiration): https://flok.cc — source at https://codeberg.org/munshkr/flok
- **Strudel** (JS port of TidalCycles): https://strudel.cc — source at https://codeberg.org/uzu/strudel
- **Hydra** (visual synth): https://hydra.ojack.xyz — synth engine at https://github.com/hydra-synth/hydra-synth
- **TidalCycles**: https://tidalcycles.org

## mok Architecture

### The two-file split

mok has a clean separation:

- **`editor.js`** — everything CodeMirror: creates editors, defines the slider widget extension, handles syntax highlighting, exports `preprocessSliders()`
- **`main.js`** — everything else: pane management, strudel/hydra/tidal eval, palette, prebake, event listeners

### Panes

Up to 3 panes, each with:
- A **CodeMirror editor** (replaces the old textarea)
- A **hidden `strudel-editor` web component** for audio (invisible, drives the Web Audio engine)
- A **target** (`strudel` | `hydra` | `tidal`)

Pane headers live in `#topbar`. Each pane has a target-switcher dropdown that's `position: fixed` and appended to `<body>` (to escape the topbar's stacking context).

### Strudel integration

mok uses the `@strudel/repl` package which exposes a `<strudel-editor>` web component. It's loaded from CDN (not bundled — too large).

```html
<script src="https://unpkg.com/@strudel/repl@latest"></script>
```

The component is kept hidden (`position:absolute; width:1px; clip-path:inset(50%)`). mok calls `evaluate(code)` on it to play patterns.

**Important**: the strudel-editor component runs code in its own sandboxed context. You can't inject variables into it from the page's `window`. This is why slider values are **substituted into the code string** (as `steady(value)`) before being passed to `evaluate()` — rather than trying to expose a `slider()` function.

**Strudel syntax in mok:**
```js
// Multiple patterns
d1: s("bd ~ sd ~")
d2: note("<c3 e3 g3>*2").s("piano").slow(2)

// Anonymous patterns
$: s("hh*8").gain(0.5)

// Sliders (value substituted as steady() before eval)
let freq = slider('freq', 440)
$: note("c3").s("piano").speed(freq)
```

See https://strudel.cc/learn for full strudel documentation.

### Hydra integration

Hydra uses the `hydra-synth` npm package, loaded from CDN:

```html
<script src="https://cdn.jsdelivr.net/npm/hydra-synth/dist/hydra-synth.js"></script>
```

A single `<canvas id="hc">` is `position: absolute; inset: 0` inside `#shell`. When a hydra pane is active, the canvas shows through the transparent pane. Other panes are `background: transparent` so Hydra visuals fill the whole screen.

`makeGlobal: true` is used so `osc()`, `out()`, `src()` etc. are available globally. Only one Hydra instance is created.

**Hydra sliders**: slider values are substituted as plain numbers (not `steady()`).

See https://hydra.ojack.xyz/docs for Hydra documentation.

### TidalCycles

TidalCycles can't run in the browser — it requires SuperCollider + a local WebSocket relay. mok shows the code and logs a message, but can't eval it without the relay.

**To set up TidalCycles locally:**
```bash
npx flok-repl@latest -H ws://localhost:3000 \
  -s <session-name> \
  -t tidal \
  -T user:maia
```
This requires running a local flok server. See https://codeberg.org/munshkr/flok for setup instructions.

## The Slider System

### How it works

1. **Detection** — `editor.js` scans the CodeMirror document for `slider(...)` calls using a regex, inside a `ViewPlugin` that runs on every document change.

2. **Widget rendering** — each `slider(...)` call is replaced with a `SliderWidget` — a CodeMirror `WidgetType` that renders an `<input type="range">` inline in the text.

3. **Preprocessing** — when you hit `Ctrl+Enter`, `preprocessSliders(code, target)` runs before eval. It scans the raw code, looks up the current value for each slider name in `sliderRegistry`, and substitutes the `slider(...)` call with:
   - `steady(value)` for Strudel (so it works as a Pattern signal — `.mul()`, `.range()` etc. all work)
   - `value` (plain number) for Hydra and TidalCycles

4. **Live update** — dragging a slider triggers `evalPane()` immediately, so changes are heard in real time.

### Slider signatures

```js
slider()                           // auto-named s1, default 0.5, range 0–1
slider(0.5)                        // auto-named, default 0.5, smart range
slider('name')                     // named, default 0.5, range 0–1
slider('name', 10)                 // named, default 10, smart range (0–40)
slider('name', 10, 0, 100)        // named, explicit range
slider('name', 10, 0, 100, 0.5)   // named, explicit range + step
```

**Smart range**: for a default value `v`:
- `min = 0`, `max = v × 4`
- `step` = one order of magnitude below `v` (e.g. default 440 → step 1)
- If `v = 0`: range is `-1` to `1`

### `sliderRegistry`

A plain object exported from `editor.js`:
```js
sliderRegistry = {
  freq:  { value: 440, min: 0, max: 1760, step: 1 },
  speed: { value: 1,   min: 0, max: 4,    step: 0.01 },
}
```
Values persist across evals — dragging sets `sliderRegistry[name].value`, which is read on the next eval.

## Prebake

Prebake code runs before each eval. Used for:
- Registering custom functions with `register()`
- Loading sample packs with `samples()`
- Setting global defaults like `setcpm()`

Separate prebake stores for Strudel and Hydra. Set via `⌘ → Load prebake…`.

**Example strudel prebake** (`prebake.strudel`):
```js
samples('github:tidalcycles/Dirt-Samples/master/')
register('acidenv', (x, pat) =>
  pat.lpf(100).lpenv(x * 9).lps(.2).lpd(.12)
)
```

Then in your code: `.acidenv(slider('env', 0.5))`

See https://github.com/switchangel/strudel-scripts for example prebake files.
